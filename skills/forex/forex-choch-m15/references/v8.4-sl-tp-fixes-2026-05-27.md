# V8.4 — SL/TP Validation & Pipeline Cleanup (27/05/2026)

## SL/TP Validation in `execute_trade()`

**Problem:** Positions being opened with:
- SL = Entry (no stop loss) — USDJPY
- SL too wide (40+ pips on $400 account) — EURUSD, USDCAD, EURJPY
- TP not matching expected RR (EURUSD RR=1.5, should be 2.0)

**Root cause:** `execute_trade()` used raw `signal['sl_pips']` without validation. SMC Fractal calculates SL as distance to swing high/low — if swing is 40 pips away, SL = 40 pips. No upper bound.

**Fix applied (27/05):**
```python
MIN_SL = 200 if is_metal else 15    # Minimum: 200t XAU / 15p forex
MAX_SL = 300 if is_metal else 30    # Maximum: 300t XAU / 30p forex

sl_pips_raw = signal.get('sl_pips', 0) or 0
if sl_pips_raw <= 0:
    return {'status': 'rejected', 'reason': 'SL=0'}  # REJECT

sl_pips = max(MIN_SL, min(sl_pips_raw, MAX_SL))  # clamp
```

| Signal | Before | After |
|--------|--------|-------|
| USDJPY SL=0 | Executed (no SL!) | **REJECTED** |
| EURUSD SL=40.3p | SL=40.3p, $8 risk | SL=30p, $6 risk |
| EURJPY SL=31.8p | SL=31.8p | SL=30p |
| XAUUSD SL=22t | SL=22t ($0.22!) | SL=200t ($2.00) |
| XAUUSD SL=1200t | SL=1200t ($12) | SL=300t ($3.00) |

Volume is recalculated after SL clamp using the validated `sl_pips`.

## ⚠️ CRITICAL PITFALL: Never call `execute_trade()` for testing

`execute_trade()` calls `send_order()` which sends real orders to MT5. Testing SL/TP math by calling `execute_trade()` opened a real EURJPY position (ticket #1671521036) and EURUSD (#1671521026). Had to close both immediately.

**Correct testing approach:**
```python
# ✅ Test calculation only — no MT5:
from forex_bot_multi import calculate_sl_tp, calculate_volume
sl, tp = calculate_sl_tp(direction, entry, sl_pips, rr, pip_size, is_metal)

# ❌ NEVER for dry runs:
result = execute_trade(pair, signal, strategy, pip, rr, balance)
```

**Validation script:** `scripts/validate_sl_tp.py` — tests all SL/TP calculations without hitting MT5.
